# Luma Health UK

Single-page marketing site for Luma Health UK, built on the same stack and folder conventions as the RPRC reference architecture.

---

## Stack

| Layer | Choice |
|---|---|
| Framework | Next.js 15 (App Router), React 19 |
| Language | TypeScript (strict) |
| Styling | Tailwind CSS v4 + custom Luma design tokens |
| Backend (future) | Supabase (Postgres + Auth) via `@supabase/ssr` |
| Testing | Vitest + Testing Library |
| Linting | ESLint 9 flat config + Prettier |

---

## Running locally

### Prerequisites
- Node ≥ 20
- Docker (for local Supabase — optional until auth is wired up)

### Without Supabase (marketing page only)

```bash
cp .env.example .env.local   # fill in placeholder values or leave them blank
npm install
npm run dev
```

### With local Supabase

```bash
# requires Docker
make dev
# or manually:
npx supabase start
npm install
npm run dev
```

App → http://localhost:3000
Supabase Studio → http://localhost:54323

## Environment variables

Copy `.env.example` to `.env.local`. For the marketing page alone, Supabase vars are optional.

| Variable | Description |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_DEFAULT_KEY` | Supabase anon/publishable key |
| `NEXT_PUBLIC_APP_URL` | Canonical site URL (used in metadata) |
| `SUPABASE_PROJECT_ID` | Project ID for `npm run types` |

## Project structure

```
app/
  page.tsx                  ← single landing page (all sections)
  layout.tsx                ← root layout with Inter + Proxima Nova
  auth/callback/route.ts    ← OAuth/magic-link exchange stub
  actions/auth.ts           ← Server Action stubs
components/
  layout/Navbar.tsx         ← sticky nav with anchor links
  layout/Footer.tsx
  sections/
    Hero.tsx                ← #hero
    Services.tsx            ← #services
    Story.tsx               ← #story
    Pricing.tsx             ← #pricing
    Contact.tsx             ← #contact
  providers/Providers.tsx   ← ThemeProvider + Sonner
  ui/                       ← primitive UI components (Button, Input, Label)
lib/
  constants/routes.ts       ← MARKETING_PATH, SECTION_IDS, sectionHref()
  constants/site.ts         ← SITE_NAME, SITE_URL, NAV_LINKS
  supabase/
    client.ts               ← browser client
    server.ts               ← server client (cookies)
    proxy.ts                ← session refresh + redirect logic
  utils.ts                  ← cn()
proxy.ts                    ← Next.js edge proxy (not middleware.ts)
supabase/
  config.toml
  migrations/               ← SQL migrations (empty until schema is defined)
types/
  database.ts               ← auto-generated by `npm run types`
```

---

## Supabase

Migrations live in `supabase/migrations/`. Workflow:

```bash
npx supabase migration new <name>   # create new migration file
# edit the SQL
npx supabase db reset               # apply locally
git add supabase/migrations/
npm run types                        # regenerate types/database.ts
```

## npm scripts

| Script | What it does |
|---|---|
| `npm run dev` | Start Next.js dev server |
| `npm run build` | Production build |
| `npm run type-check` | TypeScript check (no emit) |
| `npm run lint` | ESLint |
| `npm run format` | Prettier write |
| `npm run format:check` | Prettier check (used in CI) |
| `npm test` | Vitest run |
| `npm run types` | Generate `types/database.ts` from Supabase |

## Fonts

Proxima Nova is a commercial typeface. Place licensed `.woff2` files in `public/Fonts/` before running:

- `Proxima-Nova-Regular.woff2`
- `Proxima-Nova-Semibold.woff2`
- `Proxima-Nova-Bold.woff2`

The app falls back to Inter if the files are absent. See `public/Fonts/README.md`.
